Points en cours de édition : côté client (JS + localStorage) jusqu'au calcul ou enregistrement.

Flux de résolution

  1. Points + config envoyés en POST à /api/route/solve/
  2. Validation via SolveRequestSerializer
  3. Matrice distances : Haversine ou OSRM
  4. OR-Tools résout TSP ou PDP
  5. Réponse JSON : routes, summary, geometry
  6. Si utilisateur connecté → RouteHistory créé
  7. Frontend trace les polylignes Leaflet

Choix de conception

  • Landing + app séparées — parcours marketing puis outil authentifié
  • Sessions Django — auth simple, CSRF natif, pas de JWT
  • Vanilla JS modulaire — app.js, features.js, auth.js sans framework lourd
  • Neon Postgres — production ; SQLite acceptable en dev
  • OSRM optionnel — routes réelles vs vol d'oiseau
